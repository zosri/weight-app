# Βάρος και ενέργεια

Εφαρμογή παρακολούθησης βάρους με εκτίμηση θερμιδικής πρόσληψης.
PWA — εγκαθίσταται στην αρχική οθόνη του Android και ενημερώνεται
αυτόματα σε κάθε push από το PC.

---

## Τι υπάρχει ήδη

- Εισαγωγή βάρους· ημερομηνία και ώρα από το σύστημα
- Ρόλος ζυγίσματος (`roles.js`): μόνο το **πρώτο της ημέρας** τρέφει την τάση
- Γραμμή τάσης (EWMA, α=0.1) με διόρθωση εκκίνησης `1-(1-α)^n`
- Εκτιμώμενη πρόσληψη δίπλα στον στόχο, ενεργειακό ισοζύγιο, TDEE
- Βήματα για το χθες, μέσος όρος τελευταίων 7 πραγματικών καταχωρήσεων
- Πέντε ερωτήσεις ναι/όχι/παράλειψη, απόσυρση μετά από `MAX_SKIPS` **συνεχόμενα** skip
- Επιλογή διαστήματος, προεπιλογή 30 ημέρες
- Οθόνη ρυθμίσεων: ύψος, ηλικία, φύλο, στόχος πρόσληψης, προεπιλογή βημάτων
- Τοπική αποθήκευση, εξαγωγή **και επαναφορά** αντιγράφου ασφαλείας

### Γιατί μόνο το πρώτο ζύγισμα της ημέρας

Το βραδινό είναι συστηματικά 0.5-1 κιλό πάνω από το πρωινό. Αν μπει στην
ίδια σειρά EWMA, μία βραδινή μέτρηση σηκώνει την τάση ~70-100 γραμμάρια —
θόρυβος συγκρίσιμος με το σήμα όταν ο στόχος είναι μισό κιλό την εβδομάδα.
Τα υπόλοιπα ζυγίσματα κρατιούνται και φαίνονται ως κουκκίδες· είναι η
πρώτη ύλη για το γράφημα διαφοράς.

Το `slot` (πρωί/βράδυ/ενδιάμεσο) βγαίνει από το ρολόι και είναι **μόνο
αισθητικό**. Το πεδίο που μετράει είναι το `role`, που γράφεται ρητά κατά
την καταχώρηση. Για παλιές μετρήσεις χωρίς αυτό, το `withRoles()` το
συμπεραίνει — ποτέ από το `slot` σκέτο, αλλιώς χάνονται τα ζυγίσματα
«πρώτη μέτρηση της ημέρας» μετά τις 11:00.

## Στήσιμο, βήμα βήμα

**1. Εγκατέστησε το Node.js** από nodejs.org — την έκδοση LTS.
Άνοιξε ένα terminal και γράψε `node -v`. Αν δεις αριθμό έκδοσης, όλα καλά.

**2. Τοπική δοκιμή.** Μέσα στον φάκελο του project:

    npm install
    npm run dev

Άνοιξε τη διεύθυνση που τυπώνει (συνήθως http://localhost:5173).
Το `npm install` χρειάζεται μόνο την πρώτη φορά.

**3. Φτιάξε repository στο GitHub.** Δημόσιο, με όνομα `weight-app`.
Αν διαλέξεις άλλο όνομα, άλλαξε τη μεταβλητή `REPO` στο `vite.config.js` —
αλλιώς η σελίδα θα φορτώνει λευκή.

**4. Ανέβασε τον κώδικα:**

    git init
    git add .
    git commit -m "Φάση 1"
    git branch -M main
    git remote add origin https://github.com/ΟΝΟΜΑ_ΣΟΥ/weight-app.git
    git push -u origin main

**5. Ενεργοποίησε το GitHub Pages.** Στο repository:
Settings → Pages → Source → διάλεξε **GitHub Actions**.
Το πρώτο build τρέχει μόνο του σε 1-2 λεπτά. Η διεύθυνση θα είναι
`https://ΟΝΟΜΑ_ΣΟΥ.github.io/weight-app/`

**6. Εγκατάσταση στο κινητό.** Άνοιξε τη διεύθυνση στο Chrome →
μενού → «Προσθήκη στην αρχική οθόνη».

Από εδώ και πέρα, κάθε `git push` φτάνει στο κινητό μόνο του.
Δεν ξαναχρειάζεται τίποτα άλλο.

    src/
      tokens.js              χρώματα και γραμματοσειρά
      lib/
        metabolism.js        BMR, TDEE, θερμίδες ανά βήμα
        trend.js             EWMA, κλίση, μετατροπή σε θερμίδες
        date.js              ημέρα, ώρα, πρωί/βράδυ
        roles.js             ποιο ζύγισμα μετράει για την τάση
        questions.js         οι πέντε ερωτήσεις και τα όριά τους
        storage.js           αποθήκευση, αντίγραφα, όρια προφίλ, σερί skip
      components/
        WeightEntry.jsx      φόρμα καταχώρησης
        StatBar.jsx          μπάρα με τα βασικά νούμερα
        TrendChart.jsx       γράφημα βάρους
        MeasurementList.jsx  λίστα μετρήσεων
        Settings.jsx         προφίλ, εξαγωγή, επαναφορά

Οι υπολογισμοί ζουν αποκλειστικά στο `lib/`. Τα components δεν κάνουν
μαθηματικά — έτσι μπορείς να ελέγξεις τη λογική χωρίς να ανοίξεις UI:

    node --input-type=module -e "import {bmr} from './src/lib/metabolism.js'; console.log(bmr({weight:90.5,height:165,age:44,sex:'m'}))"

## Τι μένει

**Insight panel.** Πόσο κοστίζει σε κιλά κάθε συνήθεια. Χρειάζεται
τουλάχιστον `MIN_YES = 8` «Ναι» σε μια ερώτηση για να βγάλει νόημα.
Μέχρι τότε δεν υπάρχει τίποτα να δείξει.

**Γράφημα διαφοράς πρώτου / βραδινού ζυγίσματος.** Τα δεδομένα υπάρχουν
πλέον καθαρά: ζευγάρωσε ανά ημέρα τη μέτρηση `role === 'first'` με την
τελευταία `role === 'other'`. Μη χρησιμοποιήσεις το `slot`.

**Health Connect.** Μόνο αν σε κουράσει το χειροκίνητο Google Fit κάθε
πρωί. Στο `capacitor.config.json` βάζεις `server.url` τη διεύθυνση του
GitHub Pages: το APK γίνεται κέλυφος που δίνει native πρόσβαση στα βήματα,
ενώ το περιεχόμενο συνεχίζει να ενημερώνεται από τα push σου.

## Σημείωση για τη διόρθωση εκκίνησης

Η κλίση του EWMA υποεκτιμά την απώλεια στην αρχή — startup transient του
φίλτρου. Η διόρθωση είναι η ίδια που χρησιμοποιεί ο Adam optimizer:
διαίρεση με `1-(1-α)^n`. Δεν εξαφανίζει εντελώς την απόκλιση, τη μειώνει.
Σε δοκιμή με πραγματική απώλεια 0.070 kg/ημέρα και 20 μετρήσεις, η
διορθωμένη κλίση βγαίνει 0.056 — περίπου 80% του πραγματικού, από 71%
χωρίς διόρθωση. Γύρω στις 40 μετρήσεις συγκλίνει και η ένδειξη
«διόρθωση εκκίνησης ενεργή» σβήνει από το UI.

## Αντίγραφα ασφαλείας

Τα δεδομένα ζουν μόνο στο κινητό. Καθαρισμός δεδομένων περιήγησης τα σβήνει.
Ρυθμίσεις και δεδομένα → Εξαγωγή κατεβάζει αρχείο JSON. Κράτα ένα κάθε τόσο,
σε μέρος που δεν είναι το ίδιο το κινητό.

Η επαναφορά είναι σε δύο βήματα επίτηδες. Το `parseBackup()` διαβάζει και
ελέγχει το αρχείο **χωρίς να γράψει τίποτα**· πετάει μήνυμα αν δεν στέκει,
αλλιώς δείχνει πόσες μετρήσεις βρήκε και σε ποιο διάστημα. Μόνο μετά
διαλέγεις:

- **Συγχώνευση** — κρατά ό,τι υπάρχει, προσθέτει όσες λείπουν. Διπλότυπα
  φιλτράρονται και κατά `id` και κατά `t`. Αυτό θες σε καινούργιο κινητό.
- **Αντικατάσταση** — σβήνει τα τωρινά. Κατεβάζει αυτόματα αντίγραφό τους
  πρώτα, ώστε να μην υπάρχει κίνηση χωρίς επιστροφή.

Τα όρια του προφίλ ζουν στο `PROFILE_LIMITS` και εφαρμόζονται μέσα στο
`saveProfile()`, όχι στη φόρμα — καμία τιμή εκτός ορίων δεν φτάνει στους
υπολογισμούς από κανένα μονοπάτι, ούτε από επαναφορά χαλασμένου αρχείου.

## Μεγέθη γραμματοσειράς

Όλα τα μεγέθη ορίζονται στο `src/tokens.js`. Αν θέλεις τα πάντα
μεγαλύτερα ή μικρότερα, άλλαξε μόνο τη μεταβλητή `SCALE` στην κορυφή:

    const SCALE = 1      // προεπιλογή
    const SCALE = 1.15   // 15% μεγαλύτερα παντού

Οι μεταβλητές `T` (μεγέθη) και `W` (πάχη) χρησιμοποιούνται από όλα
τα components, οπότε δεν χρειάζεται να πειράξεις τίποτα άλλο.

Το `styles.css` κρατά το `overflow-x: hidden` και το `min-width: 0`
σε όλα τα στοιχεία — αυτά εμποδίζουν τη σελίδα να φαρδαίνει πέρα από
την οθόνη. Μην τα αφαιρέσεις.
